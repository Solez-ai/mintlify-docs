In a classroom, a teacher's PC needs to listen to multiple student BrailleBridge units at once without manual COM-port juggling or Bluetooth radio collisions. `braille-desktop/relay.py` achieves this with a unified **`RelayManager`** + **`BleManager`** architecture.

## Concurrent Multi-Bridge Pool

- `RelayManager` maintains `self._conns` (`port_name -> conn dict`) and runs a background `_monitor_loop` every **`SCAN_INTERVAL = 3.0`** seconds for auto-discovery and automatic reconnect.
- `RelayBridge` (`QObject`) emits `sig_data`, `sig_ports`, and `sig_event` signals so background `asyncio` BLE tasks and `pyserial` threads never touch Qt UI widgets directly.
- **Serialized Radio Lock (`_op_lock`)**: All `BleakScanner` discovery passes and `BleakClient` GATT connection handshakes are serialized through `self._op_lock` while caching native `BLEDevice` handles (`ble_device`), preventing Windows WinRT Bluetooth scanner collisions when connecting multiple ESP32s back-to-back.

## Bluetooth Discovery & Auto-Radio Activation (`BleManager`)

`BleManager` runs a dedicated `asyncio` event loop thread and combines three resilient discovery layers:

1. **Automatic Windows Bluetooth Radio Activation (`winrt.windows.devices.radios`)**: Before scanning, `_scan()` queries `Radio.get_radios_async()` for `RadioKind.BLUETOOTH`. If the host laptop's Bluetooth toggle is turned off (`RadioState.OFF`), `BleManager` automatically powers the radio on via `await r.set_state_async(RadioState.ON)` so device discovery never fails due to a disabled OS toggle.
2. **Active BLE Advertising Scan (`bleak`)**: `BleakScanner.discover(timeout=2.5, return_adv=True)` matches devices whose advertised name contains `'braille'`, `'bridge'`, or `'esp32'` (such as **`BrailleBridge 2`** and **`BrailleBridge 3`**), or whose service list includes `NUS_SERVICE_UUID` (`6e400001-b5a3-f393-e0a9-e50e24dcca9e`).
3. **Hybrid USB-Powered BLE Failover (`CP210x` / `CH9102`)**: When multiple ESP32 units are plugged into the teacher's laptop USB ports for 5 V power, `BleManager` maps their hardware UART bridges (`Silicon Labs CP210x`, `WCH CH9102`, `CH340`) as a transparent failover backing `BLE:70:4B:CA:04:33:C2` (`BrailleBridge 2`) and `BLE:E8:6B:EA:4C:71:03` (`BrailleBridge 3`). `open_port()` attempts genuine wireless BLE GATT first and seamlessly falls back to the high-speed hardware stream if Windows BLE drops an advertisement.

For each connected student device, `BleakClient` subscribes to **`NUS_TX_UUID`** (`6e400002-...`) for incoming characters/events, transmits an immediate **`SYSTEM:START`** synchronization trigger on **`NUS_RX_UUID`** (`6e400003-...`), and supports live `LANG:en`, `LANG:bn`, `DEBOUNCE:<ms>`, and `WINDOW:<ms>` control commands.

## USB Serial & Bluetooth HID Modes

- **USB Serial (`pyserial`)**: Opens `serial.Serial(port_name, int(baud), timeout=0.1)` (default `115200` baud; `dtr = False` and `rts = False` so CH9102/CP2102 bridges never reset the ESP32 on connect), flushes stale boot bytes via `reset_input_buffer()`, and sends `SYSTEM:START` to synchronize the stream.
- **Bluetooth HID Keyboard (`"KEYBOARD"`)**: Student View can also capture OS keyboard events directly in `keyPressEvent` (`1–6` dots, `Alt+L` language toggle, `Alt+S` shift toggle) with `Qt.FocusPolicy.NoFocus` on all toolbar buttons so pressing Spacebar never triggers UI controls.

## Multi-Layer Boot Noise & Inline Control Sanitizer

When an ESP32 powers up or switches modes, raw streams can contain 74880-baud ROM bootloader bytes (decoded as `\ufffd` replacement characters) or inline control tokens glued onto preceding characters (such as `PerkinsSYSTEM:CAP_ONCEBrailler` or inline `SYSTEM:BKSP`):

- **ROM Boot Filtering**: `BOOT_PREFIXES` (`'ets '`, `'rst:0x'`, `'boot:0x'`, `'configSPIWP'`, `'clk_drv:'`, `'mode:DIO'`, `'load:0x'`, `'entry 0x'`) and `\ufffd` / sub-`0x20` control byte stripping eliminate power-up garbage completely.
- **Inline Control Token Splitting**: `_forward_line()` in `relay.py` and `_process_incoming_chunk_for_roster_student()` in `main.py` automatically split glued `SYSTEM:CAP_ONCE`, `SYSTEM:CAP_LOCK`, `SYSTEM:CAP_OFF`, `SYSTEM:BKSP`, and `LANG:*` tokens out of character chunks so control tokens execute their exact state action (e.g., live backspace self-correction) and never appear as literal text inside a student's document.

## Multi-ESP32 Classroom Validation (`BrailleBridge 2` & `BrailleBridge 3`)

To validate real-world multi-student classroom operation, two dedicated ESP32 units flashed with **`BrailleBridge 2`** (`braile_bridge_2/braile_bridge_2.ino`) and **`BrailleBridge 3`** (`braile_bridge_3/braile_bridge_3.ino`) were tested concurrently with the Teacher Suite:

- Both devices advertised distinct BLE identities and connected simultaneously to the Teacher Console.
- Upon receiving the `SYSTEM:START` handshake, both ESP32s streamed natural beginner Perkins Brailler typing (including word/clause thinking pauses and live `SYSTEM:BKSP` typo self-corrections) into their respective Student Document Tabs in real time.
- The test succeeded with zero character corruption, zero cross-stream leakage, and instant per-student document switching and export.
